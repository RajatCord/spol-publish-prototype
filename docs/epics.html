Epic 1

Publishing workflow without AI

Finish the four-step Publish wizard without AI, built to Ankush's latest designs (Wizard 1029) and including Leo's finalization feedback. Steps: Standards and content, Readiness check, Cover and signers, Preview and publish.

Stories and acceptance criteria

  1. Apply brand colours and the preview-page design
    • Every wizard step uses the brand-approved colours.
    • Preview and publish matches the latest preview-page design.
  2. Validate the free readiness check and improve accuracy
    • The 13 checks in six categories run on real reports.
    • False positives found in validation are fixed, including proofreading.
    • The readiness score matches the documented formula.
  3. Send-back treatment and "notify all" wording
    • A sent-back standard shows the agreed treatment in the wizard and to the writer.
    • The notify option reads "notify all" as agreed.
  4. In-app alerts
    • Publishing events raise in-app alerts.
    • Alerts follow the existing Admin Communications settings.
  5. Preview: read-only images and alignment
    • Checkboxes in the preview render as read-only images.
    • Checkbox alignment is fixed.
  6. Word and PDF downloads
    • Word and PDF downloads of the report complete and match the preview.
  7. Workflow rules and form fields
    • The wizard follows the workflow rules Leo documents.
    • Form fields match Leo's confirmed list.

Not in this epic

  • AI readiness and Auto-format (E2)

Depends on

  • Leo: publishing stories, workflow rules, form fields
  • Ankush: Wizard 1029 designs

Epic 2

Publishing workflow with AI

Add AI readiness and Auto-format to the Publish workflow. AI readiness reads a report the way an accreditor's visiting reviewer would. Not started yet.

Stories and acceptance criteria

  1. AI readiness unlock card
    • The Readiness check step offers AI readiness behind an opt-in card.
    • The card quotes the credit cost before anything runs; a run never charges more than the quote.
    • The card is hidden when the account's AI switch is off (E4).
  2. Five AI checks
    • Argument strength, evidence sufficiency, consistency across standards, clarity and reviewer readiness run on the selected standards.
    • AI checks never repeat a question the free checks own.
  3. Verified findings
    • Every finding quotes the text it concerns or names the reviewer question.
    • SPOL verifies the quote exists before the finding is shown; unverified findings are dropped.
  4. Finding decisions
    • A person can accept and send back, ignore with a reason, reopen or clear each finding.
    • Nothing in the report changes without a person's decision.
  5. AI review score
    • The AI review score is shown separately from the readiness score.
    • It is never added to the readiness score and never decides whether a report can be published.
  6. Auto-format
    • Auto-format is offered in Preview, quoted first, and applied only on approval.
  7. Prompts, guardrails and test set
    • Each check has a prompt, guardrails and a test set of real reports.
    • Results on the test set are reviewed before release.
  8. Log every AI run
    • Every AI readiness run and every Auto-format run is recorded in the AI usage log (E4), named by feature and check.
    • Each record carries the prompt version and model, so results can be traced when a prompt changes.
    • What people did with the results is recorded: findings accepted and sent back, ignored (with the reason), reopened or cleared.
    • From the log we can see cost per run, per standard and per report.

Not in this epic

  • Free readiness checks (E1)
  • Writer-side AI (E3)

Depends on

  • E1: the workflow this sits in
  • E4: credit pool, metering, the overall AI switch and the AI usage log
  • Clearance to send report text and evidence to the model

Epic 3

Accreditation writer AI: Review and fix

Add AI to the narrative screen, where a writer works on the response to a standard. Version 1 reviews a response the writer has already written; it never drafts one from scratch.

Stories and acceptance criteria

  1. AI button on Edit response
    • Edit response shows an AI button that runs one action, Review and fix (4 credits).
    • The cost is shown before the run.
    • The button is hidden when the account's AI switch is off (E4).
  2. Review and fix results
    • The results show how many of the guide's requirements the response answers.
    • They show how many claims the attached evidence backs.
    • They show the number of wording suggestions still open.
  3. Accept or reject each suggestion
    • Each suggestion appears inline with an accept (tick) and a reject (cross).
    • "Accept all" accepts the remaining suggestions.
    • An accepted suggestion can be undone.
  4. Writer stays in control
    • Nothing in the response changes until the writer accepts.
    • The screen stays light on AI: one entry point, results only on request.
  5. AI inputs and rules
    • The AI is given the accreditor's guide, the response and its evidence.
    • Behaviour follows the rules Leo writes for the narrative screen.
  6. Log every Review and fix run
    • Every run is recorded in the AI usage log (E4), with the standard it ran on.
    • Each record carries the prompt version and model, so results can be traced when a prompt changes.
    • What the writer did is recorded: suggestions accepted, rejected or undone, and whether Accept all was used.
    • From the log we can see cost per run and how often suggestions are kept.

  • Cite evidence
  • Drafting from scratch
  • Modules other than Accreditation

Epic 4

AI admin: credit pool, AI switch and usage log

Build the two parts of Admin › Utilities › AI that the AI features depend on, plus the AI usage log behind them. A separate team builds the rest of the page; this epic covers only these. The log is how we calculate cost, check credits against model spend, and see what the AI is doing.

Stories and acceptance criteria

  1. Total credit pool
    • One balance, fed by every module's allocation, shows credits used out of the total.
    • The balance is the same wherever it is shown.
  2. Credit metering
    • Every AI action holds its quoted credits, charges on success and releases the hold on failure or cancel.
    • AI actions stop when the balance reaches zero, with a clear message.
  3. AI usage log
    • Every AI call, from any feature, is recorded: account, module, feature, the person who ran it, date and time, model and prompt version.
    • Each record also carries input and output tokens (reasoning included), credits quoted and charged, model cost in US dollars, duration, and the outcome (succeeded, failed, cancelled or refused).
    • Failed and cancelled calls are recorded with their reason and the credit release.
    • Credits charged and model cost can be totalled by account, module, feature, person and month, and exported.
    • The log stores no report or response text beyond what the data policy allows.
  4. Overall AI switch
    • One account-wide switch, on by default where the tier includes AI (Advanced, Enterprise), off on IE Essentials.
    • Turning it off asks for confirmation, then hides AI everywhere in the account.
    • Turning it on is not possible when the balance is zero.

Not in this epic

  • Per-feature switches
  • Who can use AI
  • Spending controls
  • Data and privacy
  • Records (the admin screen that shows the usage log)
  • Buying credits and the AI reserve

Depends on

  • Ankush: approved admin design
  • Credits per tier or institution size (decision pending; assume Advanced and Enterprise include AI, IE Essentials does not)
  • Admin page team: where the pool and the switch connect to their screens
