# Publish: engineering notes

**Reference material, not the specification.** This is the earlier, technical version of the handoff: a proposed data model, service contracts, ledger rules, audit entry names and per-control accessibility attributes. The product specification is the [functional handoff](handoff.html); where the two differ, the functional handoff wins, and the build team owns the technical design. The readiness score formula in these notes is superseded by readiness-score v1, defined in "The readiness checks".

Everything the development team needs to build the polished Publish workflow as prototyped: scope, the data model, the state machine, each screen control by control, the AI calls, credits, audit, accessibility, acceptance criteria and the open questions. Nothing here adds a goal the prototype does not show; it makes the prototype precise.

## In short

- **What:** the Publish tab becomes a landing page plus four steps: Standards & content → Readiness check → Cover & signers → Preview & publish. Generate Report is folded into step 4.
- **Quality leaves the workflow through Send back;** nothing is fixed inside Publish. Formatting is fixed by Auto-format (AI, 4 credits). AI readiness is opt-in (2 credits per standard + 5).
- **A draft can be published any time.** A final needs every selected standard approved, three confirmations after every section is viewed, and no unresolved injection flag.
- **Everything is recorded:** runs, decisions, confirmations, publishes, deletions, with who, when, which report version.

## Data model (new or changed)

Five decisions the model rests on: (1) a **Snapshot** stores references to immutable repository versions plus derived passage text and hashes, never full copies; only publishing stores a rendered asset. (2) **draft_number** is assigned when a version is created, **final_number** when a final is published; numbers are never reused, a withdrawn final keeps its number. (3) Step 4 edits are **version-local overrides** in the snapshot; the repository is written only when "Also update the response in All Accreditation" is ticked, through the standards service as a new narrative version. (4) **Exclusions** are derived from open SendBacks per publication, never a flag on the version. (5) One **rev** per version (the ETag) covers the row, selection, cover and confirmations; section views, runs and finding decisions do not bump it; every write of the version row requires If-Match.

### Hashes

- `content_hash` = hash over included items' (passage hashes, judgement, chain_state, attachment versions, open comment ids) + selection + settings + response type + format_ops. Auto-format changes format_ops, so it is covered.
- `item.input_hash` = hash(standard text, guidance, rubric, cleaned passages, evidence index with extracts, judgement, human comments), computed before pseudonymisation.
- `a1_key` = hash(input_hash, pipeline_versions, model, rubric_version, accreditor); `a2_key` = hash(sorted a1_keys, A2 versions).

## States, gates and events

### Version lifecycle

```
in_progress ──(Publish draft)──▶ published(draft)       immutable: every write returns 409 "published"
in_progress ──(Publish final)──▶ published(final)       only when final_ready = true
published(final) ──(Withdraw, coordinator)──▶ withdrawn  file stays downloadable, marked Withdrawn; Final numbering continues (Final 2)
in_progress ──(Delete, confirm)──▶ deleted               published versions never delete
any published ──(Start Draft n+1 / Duplicate)──▶ new in_progress version, created on demand only (never automatically)
published(draft) ──▶ cannot be withdrawn or deleted (it is an internal record; Start Draft n+1 instead)
in_progress with a run in flight ──(Delete)──▶ the run is cancelled first (AI: in-flight standards settled, the rest refunded; Auto-format: refunded), then deleted
```

**Duplicate** takes the current template revision and copies the source version's selection, settings, cover and output; it is offered on any published or withdrawn version, never on a live draft (that would fork it). Exclusions are carried by reference: the open SendBack rows belong to the publication, so Draft n+1 reads the same rows and sees them lift when the item returns.

**Orthogonal state** each version carries: `stale`, the three confirmations, and `in_flight` (none | ai | autoformat | publish; a preview build is not in flight, it only locks confirmations through confirmations_unlocked). "Clear confirmations" always means null all three and write `version.unconfirmed{cause}`.

**What Draft n+1 inherits:** selection, content settings, response type, cover and output settings. **Not inherited:** confirmations, viewed sections, readiness and Auto-format runs. AI finding decisions carry over when the finding's (input hash, kind, anchor) still matches; "Will fix after this draft" reopens. Send-back exclusions carry until the standard returns.

**AiRun status** adds `approval_expired` (7 days without a decision; reservation released; card returns to the quote with "Approval expired · Ask again"). `awaiting_approval` is not in flight: it blocks nothing and the draft can be published meanwhile; the run, when approved, uses the snapshot it was quoted on, and if that snapshot is no longer current the quote is void (409 "The draft changed since the quote · Quote again").

**AiFinding status** is derived: `open` (no decision, or reopened) · `sent_back` (accept decision with an open SendBack) · `closed` (ignore, or clear for injection) · `superseded` (the result key that produced it is no longer in the latest run, because the input changed and the finding did not recur; shown greyed under "Resolved by the latest run", no buttons). When a new run reproduces the same finding_key, the previous decision carries, whatever draft it was made in. Accept and Ignore are refused on an injection finding (only Mark cleared applies), and an injection finding keeps blocking a final even when outdated until it is cleared or superseded. A send-back prefill lists the standard's open findings with each one ticked; unticking one leaves it open.

**A standard returning from send back:** when the chain reports it resubmitted or approved, SPOL sets `SendBack.returned_at`, lifts the exclusion, marks readiness stale, clears the confirmations (cause recorded) and shows "{code} came back from {name} · included again · run checks again". Its AI findings stay sent_back until the next AI run. The banner reads "included again" only when the send back had excluded it; otherwise "{code} came back from {name} · run checks again". A chain approval that arrives without a send back only recomputes final_ready (no banner, no clearing). An exclusion is lifted only by the item returning; there is no manual lift, and a standard that is sent back outside Publish cannot be excluded from this version (the coordinator unselects it in Step 1 instead).

### Gates (computed, shown as text wherever they block)

Definitions. `excluded` = selected items with an open SendBack where exclude is on. `in_flight` = an Auto-format, AI readiness (status running only; awaiting_approval does not block) or publish job is running for this version; a rules run never blocks. `stale` = no completed rules run, or the run's snapshot content_hash ≠ the current snapshot's. Every gate below is evaluated server-side on every POST as well as in the client; a POST that fails a gate returns 409 `{code: "gate", blockers[]}` and records nothing.

| Gate | True when | Blocker order and message |
| --- | --- | --- |
| can_start | role ∈ {coordinator, editor} ∧ ¬impersonating ∧ source, cycle and template chosen | "Only coordinators and editors can do this" → "Not available while impersonating" → "Choose a report template to start" |
| cover_valid | submit_by after today (drafts and finals) | Step 3 inline error; Step 4 blocker "Submit date must be after today" |
| signers_complete | preparer, CEO and liaison each have a current holder (finals only) | Step 3 "No one holds this role · Assign in Admin" (not an error); Step 4 Final blocker "Add the three signers in Cover" |
| confirmations_unlocked(user) | status = in_progress ∧ role ok ∧ ¬impersonating ∧ preview complete ∧ the user has viewed every section of the current snapshot | "Published versions can't be changed" → "Only coordinators and editors can do this" → "Not available while impersonating" → "Preparing the preview · {n} of {N} pages" → "View all {N} sections to confirm ({k} viewed)" |
| draft_ready | all three confirmations present (any confirmer; each entry keeps its own by/at) | "Confirm {3−c} more to publish · {v} of {S} sections viewed" |
| draft_publishable | status = in_progress ∧ role ok ∧ ¬impersonating ∧ \|selected ∖ excluded\| ≥ 1 ∧ ¬in_flight ∧ file_name ≠ "" ∧ cover_valid ∧ draft_ready | 409 published → role → "Not available while impersonating" → "Nothing to publish" → "Wait for {Auto-format \| AI readiness \| publishing} to finish" → "File name can't be empty" → "Submit date must be after today" → draft_ready message |
| final_ready | draft_publishable ∧ signers_complete ∧ excluded = ∅ ∧ every selected item approved ∧ no injection finding without a clear decision ∧ ¬stale | draft_publishable reasons → "Add the three signers in Cover" → "Not yet: {codes} not approved or excluded by send back" → "Text that tries to steer the review was found in {code} · clear it in Readiness" → "Readiness check out of date · Run again" → draft_ready message. On the Published screen the "Final · Blocked · reason" line is evaluated for a hypothetical Draft n+1 and its action is "Start Draft n+1". |
| readiness_stale | see `stale` above; a new snapshot is taken on: selection, settings or response-type change; an item removed from the cycle; narrative, evidence or comment change on a selected item (feed); Auto-format apply or undo; an edit save; a send back that excludes; a return from send back | Step 2 "Out of date · Run again" (or "Not checked yet · Run checks" when no run exists); Step 4 banner after Edit, Auto-format or Undo |

### What clears the confirmations

- Any saved edit in Step 4 Edit mode (a discard clears nothing).
- Auto-format applied, and Auto-format undone (the document changed either way).
- A change to the selection in Step 1, the content settings, or the response type; a standard removed from the cycle.
- A send back that excludes a standard, and a standard returning from send back.
- A readiness run or an AI run whose finding set differs from the previous one clears only "Findings and comments" (its summary changed); the cause is recorded.
- **Not cleared:** a narrative, evidence or comment change arriving from the feed. The draft goes stale and Step 4 shows the banner, but confirmations stand: a draft tolerates text that moved under it (it is internal); a final does not, because final_ready requires ¬stale, and a re-run that changes the finding set clears "Findings and comments".
- A confirmation can be unticked by any coordinator or editor, not only the person who ticked it; the audit entry records both.

### Roles and impersonation

- Writers may open a version and read every step; Start, Delete, Withdraw, Send back, Unlock, Auto-format, confirmations and Publish are aria-disabled for them: "Only coordinators and editors can do this". Accept, Ignore and Reopen on AI findings are coordinator or editor only.
- While impersonating, Start, Publish, Send back, Unlock, Auto-format, Delete and confirmations are aria-disabled: "Not available while impersonating". Section views are not recorded either (POST …/views → 403), so an impersonator can never unlock confirmations for the person they impersonate.
- Any 403 on a write: "You no longer have access to this publication. Back to Publish."
- A published version opened from the landing shows Published; steps 1–3 are read-only with controls aria-disabled: "Published versions can't be changed".

### Defaults the screens assume

- Quote `expires_at` = 15 minutes after the quote; `planned_finish_at` = start + 20 s per standard ÷ 4 parallel calls + 60 s for A2, minimum 2 minutes.
- Search debounce 300 ms; autosave debounce 1 s. Sizes print as "2.3 MB" (one decimal, binary MB). "Last edited" is an absolute date "{d Mon yyyy}".
- `step_reached` advances when Next succeeds and never falls; reload opens the step in the URL, capped at step_reached.
- Section views persist while the section id persists across snapshots; a document section new to the current snapshot counts as unviewed.
- Writes during a running AI run are allowed (a new snapshot marks the run's result stale on completion, "Out of date · Run again"); only publishing waits.
- The preview build starts on entry to Step 4 and after every new snapshot; its limit is 2 minutes, publishing's is 5 minutes, after which "Publishing is taking longer than usual · we'll keep going; you can leave this page" (the job continues; the landing row shows "Publishing…").
- Rename publication: inline dialog, 1–120 characters, trimmed, unique within the cycle ("A publication with this name already exists").
- File name: prefilled "{Institution}_{Source}_{Title}_{Label}_{yyyy-mm-dd}" without spaces; spaces typed are kept; \ / : * ? " < > | removed; over 120 characters truncated with the note "Shortened to 120 characters".
- Impersonation: every write returns 403, including autosave PATCH (controls are read-only, "Not available while impersonating").
- Second approval: any other coordinator of the institution; when none exists, the dialog reads "A second coordinator must approve · none is set up · Ask your administrator" and the run cannot start.
- "Reviewer view: {n} likely follow-ups" = number of high AI findings across checked standards.
- Confirmation titles and summaries: "Sections and standards · {n} standards in {m} sections · Not approved: {codes}", "Formatting and branding · Logo {file} · {cover letter or No cover letter} · Fonts embedded, page numbers continuous", "Findings and comments · {n} open findings carried from Readiness · {m} open comments".

### Navigation and saving

- Each step is a URL `/publish/versions/{id}/step/{n}`; reload opens that step, never beyond step_reached; browser Back moves one step.
- Autosave on every change, debounced 1 s: "Saving…" → "Saved"; on failure "Couldn't save · Retry". A 412 reverts the control to the server value, refetches, and announces "Someone else saved this draft. Reload." No merge.
- A draft deleted elsewhere returns 410 on the next request: "This draft was deleted by {name}. Back to Publish."
- Published elsewhere while open (change feed): "Draft 4 was published by {name} at {time} and can't be edited. Start Draft 5 · View published". Unsaved edits are lost and the notice says so.

## Credits, ledger and what the coordinator sees

- **AI readiness:** 2 credits per standard whose result is not already stored + 5 for the consistency pass. The quote is the charge; it is what the card shows ("29 credits for 12 standards"; when some are stored: "21 credits for 8 standards · 4 already checked"). "{n} left this year" always shows **available** = balance − open reserves, never the raw balance.
- **Hold = charge.** The reservation holds exactly the charge in credits. The 1.5× figure is the run's USD spend budget inside SPOL, not a credit hold: the institution never pays more than the charge, and a standard whose retries exceed the budget is "not checked: retry budget" and refunded. 402 when available < charge: "Not enough credits · 29 needed, 20 left this year · Ask your administrator".
- **Refunds:** 2 credits per standard not checked after the charge (ungrounded, retry budget, provider unavailable, refusal, cancelled, timed out); standards excluded at quote time (too long, personal data) are never charged and are listed in the quote. The 5 consistency credits are refunded whenever A2 does not run (any A1 not checked, cancel, timeout).
- **Approval:** above 50 credits a second coordinator approves (never the requester). The reservation is taken at the request and released on decline or after 7 days (approval_expired / approval_declined). The approver sees "{name} asks you to approve AI readiness on {label} · {charge} credits · Approve · Decline"; the requester's card then reads "Approved by {name} · Reading…" or "Approval declined by {name} · Ask again".
- **Auto-format:** the deterministic candidate scan runs first. No candidates → "Nothing to format · no credits used", no ledger entry, audit autoformat.run{status: nothing_to_format}. Otherwise reserve 4 → settle −4 on done; on failure settle 0 and "Auto-format couldn't finish · no changes applied · nothing charged · Try again". Undo never refunds; the dialog says so ("Undo doesn't return the credits").
- **Delete** releases any open reservation on the version, including one awaiting approval (settle 0, audit ai_readiness.run{status: cancelled, cause: deleted}).
- **Everything else in Publish is free** and never labelled AI: the rules readiness, Send back, Remind, publishing in any format. Writers never see balances or cost lines.
- **Provider down before any call:** release, no charge, "AI readiness isn't available right now · nothing was charged · Try again".

### Ledger rules (invariants the tests assert)

- balance = Σ(settle, refund, purchase, allowance). A `reserve` entry never changes balance_after; it opens a reservation. available = balance − Σ(open reserves).
- A reservation is open until exactly one `settle` entry carries its reservation_id (UNIQUE). A release is a settle of 0. A `refund` is a positive entry with the same reservation_id written in the same transaction as the settle. Every settle is ≤ its reserve in magnitude, so balance can never go negative.
- The reserve check and insert are one serialised write per institution; two coordinators on a shared balance that covers one run get one reserve and one 402.
- Cancel, the reaper and a retried POST …/cancel call one close routine that no-ops when a settle exists. Results arriving after close are stored (free next time) but never charged. Standards in flight at cancel finish, count in "{n} of {N} checked" and in the next quote.
- Amounts are signed integers. Both ai_readiness.run and autoformat.run audit entries carry reservation_id and the ledger entry ids so the audit reconciles to the ledger.

## Accessibility requirements (WCAG 2.2 AA)

- One h1 per page (Accreditation), the page title is h2, sections h3. Skip link to main.
- Every disabled control uses aria-disabled (stays in the tab order; Enter/Space do nothing) with aria-describedby to its reason text; never a tooltip-only reason and never the disabled attribute.
- Every control that performs an action is a `<button>`; only navigation is a link. (The prototype uses links between artboards; do not copy that.)
- Dialogs: role=dialog, aria-modal, labelled; focus moves in (initial focus named per dialog below), background inert, Esc and Cancel return focus to the opener. When the opener is removed by the action (Send back, Accept), focus moves to the row's new chip (tabindex=-1).
- Status never by colour alone: dot + word; score rings role=img with the score and verdicts in the label; bars aria-hidden with their value in text beside them.
- Contrast: text 4.5:1, control borders and icons 3:1. Input and segmented borders are #8a95a1 (3.1:1); the AI button gradient ends at #7c3aed (white text 5.1:1); hairline separators (#e6e9ee) are decorative only. No strikethrough on closed findings; the chip carries the state.
- Targets ≥ 24 × 24 px on desktop (inline text actions get padding to reach it), ≥ 44 px on phone; focus visible on navy and white.
- Live regions: counts, "Saved", progress and completion use role=status; errors use role=alert and receive focus.
- Reading mode and the viewer are keyboard-operable: Page Down/Up, Home/End, Find (Enter next, Shift+Enter previous, "{i} of {n} matches" role=status), Esc exits.
- Native semantics first: tabs are role=tablist/tab/tabpanel with arrow-key movement; row ⋯ menus are role=menu opened by a button with aria-haspopup and aria-expanded, Esc closes and returns focus; every radio group is native `<input type=radio>` inside a label (Content settings, Response type, Send to, Version), the custom dot is decorative; expandable standard rows are `<details>`/`<summary>` so the chevron needs no script; each selectable sentence in the review panel, Preview and reading mode is an inline `<span role=button tabindex=0>` with aria-pressed and Enter/Space handling (a native button cannot flow inline through a paragraph: browsers render it as an inline-block, which breaks the line and centres the text).
- **Automated check, 20 Oct 2026.** axe-core 4.10 (WCAG 2.0/2.1/2.2 A and AA plus best practices) run on the live prototype site over the landing, Steps 1 to 4, reading mode, the review panel, the before-and-after view and the send-all dialog: zero violations after fixes (landmarks for the wizard header and footer, reading-mode header and main, heading levels, named confirm checkboxes, no links inside <summary>, dialogs on <div> not <aside>, focusable scroll regions, the blurred locked panel keeps full-contrast text). One finding left by design: axe reports the selectable sentences as targets under 24 px; they are inline text in a paragraph, which WCAG 2.5.8 exempts, and every sentence can also be reached with Tab and Enter. Colour contrast "incomplete" items are the blurred preview behind the unlock card, which is aria-hidden.
- Bulk actions are explicit: Send all back lists every standard it will touch with who receives it and what the comment contains, defaults to all ticked, and names the count on the primary button; nothing is sent for a standard the person cannot see in the list.
- Placeholders are not labels: every field has a visible label and a hint with an id; placeholder text is #5f6b7a (4.6:1). "Select a template…" is a placeholder option, never a submitted value.
- Reflow: at ≤ 1100 px the Preview grid drops the thumbnail rail and the Confirm column stacks under the document; at ≤ 900 px the reading-mode Comments panel becomes a bottom sheet (max 60 vh) and the Readiness, Review and Before/after grids go single-column; at 390 px nothing scrolls horizontally and every action stays reachable (WCAG 1.4.10).
- Reflow: at 320 px / 400% zoom nothing scrolls horizontally except the document viewer and data tables inside their own box.
- Native date inputs show a locale placeholder that looks like a value; keep the "Leave the dates blank…" hint linked by aria-describedby and never prefill a signed date.

12. **Delete with a run in flight.** Given an AI run with 6 of 12 done. When the owner deletes the draft (confirm dialog adds "An AI readiness run is in progress and will be cancelled"): run cancelled and settled, version deleted, both audited.

### 4 · Severity of system findings

Three levels, one meaning each, applied by the rule, never by a person: **High** — the published document would be wrong, incomplete or unprintable for a reviewer, or a final cannot be submitted; **Medium** — a reviewer would notice and ask, or evidence or review is incomplete; **Low** — polish, fixed by a tool or safely ignored. Only High and Medium count in the rules score (−2 and −1 per finding on a standard); Low never does; report-wide findings never do; an unapproved selected standard costs −6 regardless of findings. One finding per element: a table with nine wide columns is one High, not nine, so the counts stay honest (the v6 build's "181 table issues" is counting cells).

| Check | High | Medium | Low | Not checked when |
| --- | --- | --- | --- | --- |
| Spelling, grammar, punctuation (WProofreader) | — | A misspelt word not in either dictionary | Grammar, punctuation; a word the institution's dictionary knows but SPOL's does not | Language service unavailable; narrative empty |
| Style (WProofreader rules) | — | A rule the institution marked "required" in its style guide | Every other style rule | No style guide configured |
| Link validation | A linked SPOL document or evidence file that no longer exists or the reader cannot open (the v6 "Document file not found on server") | An external URL answering 4xx/5xx or timing out twice; an objective or outcome reference to a deleted item | A URL that redirects (301/302) or whose certificate warns | No network; the link target is behind sign-in |
| Table format | Wider than the printable page at 100 % (cells would be cut off) | No header row; a table that splits a row across pages | Fits only after scaling below 85 % (Auto-format will turn it landscape) | Table has no computable width (nested or malformed) |
| Image sizes | Larger than the page so it would be cropped | Over the size limit (1 MB) or under 150 dpi at print size | Within limits but without a caption | Image file missing |
| Alt text | — | An image with no alt text | Alt text identical to the file name | — |
| Headings | — | A skipped level (H4 under H2); an empty heading | Duplicate numbering | — |
| Illegal characters | A file name that the export or the file system rejects (`\ / : * ? " < > \\|`, control characters) | A narrative character on the institution's list in System Settings (as in v6) that breaks export or rendering | A character SPOL will substitute silently (smart quotes to straight, non-breaking spaces) | — |
| Missing attachments | Expected evidence count set and nothing attached; or the expected count not set at all (the standard cannot be judged complete) | Fewer attachments than expected | More than expected | Standard not started |
| Placeholder text | Bracketed or templated placeholder, "TBD", "lorem" in the narrative or on the cover | — | — | — |
| Required cover fields | Institution name, address, preparer, a required signer or the submit date missing (blocks a final, not a draft) | A signer named but their date unsigned | — | — |
| Open comments and unresolved edits | — | An open comment or a pending tracked change on the standard | — | Comment service unavailable |
| Hidden text (cleaner) | Hidden text found and removed (report-wide; shown so nobody is surprised) | — | — | — |
| Not approved | Not a finding: a chain state shown on the row and charged −6 in the score | — |  |  |

AI findings keep their own scale, decided by the model and validated by SPOL: High — a committee would likely cite it; Medium — it would ask; Low — wording. They never enter the rules score. A check's row status is **Passed** (ran, nothing found), **Issues found** (with the count of findings, not of cells or words), **Partially checked** (ran but some standards or items could not be checked, with the reason) or **Not checked** (did not run). "Issue Summary" in the v6 build is a view, not a check, and should not appear in the checks table.
